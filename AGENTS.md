# Repository guidance

- All repository content must be written in English, even if some existing content is in Spanish, the developer's native language.
- Follow `docs/contributing.md` for branch names, commit messages, and PR titles/descriptions.
- Start with `docs/challenge.md` for requirements. `docs/brainstorming.md` contains proposals, not an implemented architecture; its folder tree, BFF label, and Azure deployment idea are not established facts.
- The backend is at `src/backend/BlaChallenge.slnx`: .NET 10 Domain, Application, Infrastructure, and ASP.NET Core API projects, each with an xUnit test project and Coverlet. User registration, JWT authentication, SQLite persistence, task CRUD, role-based authorization, and API tests are implemented. The React frontend is at `src/frontend`.
- From the repository root, use `dotnet restore src/backend/BlaChallenge.slnx`, `dotnet build src/backend/BlaChallenge.slnx --no-restore`, and `dotnet test src/backend/BlaChallenge.slnx --no-build`. Current tests cover authentication and persistence; do not report them as task or frontend coverage. See `README.md` for API launch profiles and URLs.
- The challenge prohibits Entity Framework, Dapper, and “Mediator.” The last term is ambiguous about library versus pattern; do not assume a homemade mediator is allowed. CQRS can use direct calls to use cases.
- The backend must use .NET/C# and Clean Architecture, with business rules independent of persistence and API code. Application references Domain; Infrastructure references Application and Domain; API references Application and Infrastructure. Preserve inward-facing dependencies. SQLite and JWT Bearer are confirmed for the current backend iteration; the frontend uses React/Vite, React Router, Zustand, TanStack Query, and Zod.
- Plan tests alongside implementation: the challenge calls for coverage of data access, business logic, and API endpoints, and introduces TDD as the development approach.
- Preserve evidence of GenAI work as it happens: prompts, representative generated code, validation, corrections, and handling of edge cases/authentication. This is part of the assessed deliverable, not just optional documentation.
- Use sequential, zero-padded identifiers for documentation review headings, such as `Documentation Review 001`, rather than dates. Increment the identifier for each new review (`002`, `003`, etc.) and use the same identifier when recording that review in `docs/development-log.md` and `docs/genai.md`.
- Delivery must include an informal user story, setup instructions, seeded demo data/credentials, and a presentation demonstrating and explaining the implementation. Consult the challenge for the full acceptance criteria.
